# 粉体粒径档表 · 多批合并 P90 最紧界核算（外存作业版）

按批号上传粉体粒径**档表**（连续排列、互不重叠的整数微米闭区间），同批可补报
同一组粒子的不同分档表（入库前做整体相容性校验）；在网页勾选多批后，后台**作业**
计算合并后 **P90 的最紧上下界**，并各产出一份能真实取到该端点的**逐批粒径频数
见证 CSV**。全程按档运算，不逐粒展开；大批量档表与见证落到本地磁盘，**工作内存
至多随所选批次数 B 与最大单批档数 M 线性增长（O(B+M)）**，合计百亿粒也按档完成。

## 启动方式

### Docker Compose（推荐演示）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
# 另开终端灌入演示数据（容器内）：
docker compose exec web python -m scripts.seed
```

SQLite 数据文件保存在命名卷 `powder-data`（容器内 `/app/data/powder.db`），
核算作业的快照、外存暂存与见证 CSV 保存在 `/app/data/jobs/`，容器重建不丢数据；
健康检查命中 `GET /`。gunicorn 固定 **2 个工作进程**。

### 本地 Python

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

gunicorn -w 2 -b 0.0.0.1:8000 app.main:app
```

## 网页演示流程

1. **上传**：批号 `B-ALPHA`，粘贴（每行 `lo hi count`，空格或逗号分隔）：
   ```
   0 99 400
   100 199 500
   ```
2. **相容补报**：同批号再贴一张更细的分档表，提示“补报成功”，该批现有 2 张档表：
   ```
   0 49 100
   50 99 300
   100 149 400
   150 199 100
   ```
3. **不相容补报（被拒绝、不入库）**：同批号贴
   ```
   0 49 450
   50 99 0
   100 199 450
   ```
   页面给出冲突切割点与原因；批次详情里仍是原来的 2 张档表，后续核算只按
   已入库档表进行。
4. **勾选批次 → 核算**：提交后生成一个后台作业并跳转作业页（每 2 秒自动刷新）。
   作业完成后展示总粒数、k=⌈0.9N⌉、P90 最紧下界/上界，以及**两端完整逐批频数
   见证 CSV 的下载入口**；作业失败时页面给出具体原因，且不出现下载入口。

## 外存作业与快照语义（网页实际路径）

`app/engine.py` 是网页核算实际调用的外存实现，解决一次核算许多批次时档表和见证
占满内存的问题：

1. **一致性快照**：作业开始即用 SQLite backup API 把主库复制到作业目录。上下界、
   见证、全部复核都只读该快照。**同批补报照常写入主库，不影响在途作业；下一次核算
   重新备份，自然采用新档表。** 上下界与见证因此严格对应核算开始时的同一已提交状态。
2. **分块暂存（SpoolArray）**：定长 int64 数组按 256KiB 一块顺序写/顺序读，写满即
   落盘，读游标只缓存一块。每个读游标独占文件句柄、读尽即关，句柄数有常数上限。
3. **外部归并**：每批档表切割点用二路外部归并落盘，全部批次再做 B 路堆归并得到
   全局切割点（堆 O(B)，不物化全局数组）。
4. **走廊在全局点上流式折叠**：每张表的 S/E 由双指针惰性游标在全局切割点上求出，
   L=max S、U=min E 逐表流式折叠到暂存；相容性在同一遍扫描里校验。
5. **见证流式化**：在全局切割点上对每批 L/U 差分，逐批流式写 CSV；先逐表流式复核
   频数符合本批**全部**档表（单表归并数组 O(M)），再用 B 路堆归并复核两端各批频数
   合并后第 k 粒**恰好**取到对应 P90。最后拼成两端完整 CSV。
6. **内存边界**：常驻内存只含分块缓冲（常数）、B 路归并的 O(B) 游标/堆，以及单表
   复核的 O(M) 归并数组，即 **O(B+M)**，与总档数、总粒数无关；全量数据落在本地磁盘。

作业状态（running/ready/failed）落 `jobs` 表，详情落作业目录 `meta.json`（原子替换）。
只有两份见证齐备且逐表、合并复核全部通过，状态才为 ready，页面才显示下载入口；
核算或暂存失败时状态为 failed 并展示原因。

## 算法要点（按档计算，不展开粒子）

对档表 T 记切割点 `cuts=[lo0, hi0+1, hi1+1, …]` 与档累计 `cum`。对任意整数
切割点 c，任一相容粒子组中“粒径 < c 的粒数”被夹在：

- `S_T(c)`：完全位于 c 左侧（`hi+1 ≤ c`）的档粒数和（下界）；
- `E_T(c)`：档起点 `lo < c` 的档粒数和（上界）。

一批所有档表的切割点取并集，该批的累计走廊为逐点
`L(j)=max_T S_T(c_j)`、`U(j)=min_T E_T(c_j)`。**多表相容 ⇔ 总粒数一致且
处处 L(j) ≤ U(j)**（在表自身切割点上 S=E，CDF 被钉死，走廊宽度只出现在档内）。

多批各批独立，合并走廊为各批 L/U 之和。设 `k=⌈0.9N⌉`：

- 最紧**下界** = 首个满足 `U(j+1) ≥ k` 的原子段 `[c_j,c_{j+1})` 的左端点；
- 最紧**上界** = 首个满足 `L(j+1) ≥ k` 的段的右端点 `c_{j+1}-1`。

见证（每批一份，合并后第 k 粒恰为端点）：

- 下界见证：段 j 放 `U(j+1)-U(j)` 粒、堆段左端（CDF 处处贴 U）；
- 上界见证：段 j 放 `L(j+1)-L(j)` 粒、堆段右端（CDF 处处贴 L）。

所有 S/E 序列由双指针线性归并得到，复杂度 O(表数 × (档数 + 全局切割点数))，
空间与档数同阶，与粒数无关。

## 约束与语义

- 档：非负整数 `lo ≤ hi`，档间首尾相接、互不重叠；粒数非负，整表至少一粒；
- 允许零粒档；允许补报表用零粒尾档把覆盖范围往外扩（不要求新粒子）；
- 同批各表总粒数必须相同；冲突时整次补报拒绝，不写库。
